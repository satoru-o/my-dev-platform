新しい要望の雛形を、対話で作る。引数: `$ARGUMENTS`（最初の語がslug、残りはひとこと説明）。

## 手順
1. slugを検証し、採番し、重複を確認する（今までと同じ）。
   - slug（英小文字・数字・ハイフンのみ）が不正（日本語など）なら、ひとこと説明から英語のslugを提案し、OKをもらってから進む。
2. 最初の質問を1つだけする: 「振る舞いは変わりますか？ a) 変わる b) 変わらない（依存・整形・リファクタ・ドキュメント）」
3. b の場合: `kind: chore`（または refactor）、`size: S0` とし、受け入れ条件は「既存テストが全件通る」と、人間が挙げた確認項目（例: 警告0件）にする。具体例は要らない。依存の追加や更新なら、「根拠」欄に、確認したURLと人間の確認チェック `[ ]` を置く。
4. a の場合（`kind: feature`）: ひとこと説明を、言い換えずに「やりたいこと」へ転記する。足りなければ聞く。
5. 受け入れ条件ごとに、日常の言葉で聞く: 「〇〇したら、どうなってほしいですか？例を1〜3個」。人間の答えは、**言い換えず、そのまま**表に転記する。
   - AIが案を出したいときは、質問の選択肢（シナリオ + 選択肢 + 推奨）の形でだけ出す。
   - 転記した行の末尾に、出典を付ける: 人間が自分で述べたら `[人]`、AIの案を選んだら `[案→承認]`。選ばれなかった案は書かない。
   - 期待値は、推奨で進めない。未回答なら空欄に `⚠️ 未回答` と書く。
6. 「やらないこと」「制約」は、AIが暫定案を出し、人間が OK か修正を返す。
7. `size` と `risk` は暫定値を提案し、「暫定・要確認」と明記する。
8. 最後に次の一歩だけ伝える: 「`⚠️ 未回答` があれば埋めてください。無ければ `/req-run NNNN`」。

## やらないこと
- discussion-log.md、test-plan.md、テスト、実装を作らない。
- 既存の req.md / status.md を上書きしない。
