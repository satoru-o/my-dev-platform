# 個人ラボ企画書：TDD x SDD x Skills x 開発環境

## 背景と課題

AIでコードとテストを速く作れるようになった今、ボトルネックは「信頼」と「レビューの手間」に移っています。

- AIが書いたコードとAIが書いたテストは、同じ勘違いを共有しやすく、テストが通っても安心できません
- 人間が全PRを読む運用は、AIの生産速度に追いつかず、疲れて雑になります
- 新しいプロジェクトのたびに環境を作るのが面倒で、実験の始まりが遅くなります
- devcontainerに移ると、これまでのClaude Code履歴が見えなくなり、過去の知見を使いにくくなります

## ゴールと成果物

ゴールは、AIと速く、かつ安全に作れる「自分用の型」を持つことです。成果物は次の4つです。

1. テンプレートリポジトリ：TypeScript、Vitest、devcontainer、CLAUDE.md、test-reviewer入り
2. 開発の型：仕様を先に書くSDDと、テストを先に書くTDDの進め方と、AIへの指示
3. Skills：仕様を書く、失敗するテストを1つ書く、PRを見るなど、繰り返す作業の再利用部品
4. PR運用：ブランチ保護、CODEOWNERS、AIレビュー、docs系の自動マージ

## 全体像

人間は「何を作るか」と「期待値」だけを決め、書く作業はAI、確認は機械に任せる構成です。柱は3本です。

| 柱 | 中身 | 役割 |
| --- | --- | --- |
| 開発の型 | 仕様(SDD)、テスト(TDD)、実装の順 | 人間が仕様と期待値を決め、AIが書く |
| Skills | 仕様作成、Red確認、PRレビューなどの部品 | 型を毎回書かずに呼び出せる |
| 環境 | devcontainer、テンプレート、履歴の引き継ぎ | 始めるまでの手間をなくす |

この3本を支える「壁」は、人間のレビューではなく機械のルールで作ります。.github、CLAUDE.md、.claudeの変更は人間の承認を必須にして、AIが自分でルールを書き換えられないようにします。リリースの認証情報はPR側に置かず、別ワークフローに分けます。

## スコープ

今回はPR周りと開発環境に絞り、リリース系は含めません。

**やること**

- devcontainer内でClaude Codeの履歴を見られるようにする
- テンプレートリポジトリと、TDD、SDDの進め方の整備
- Skillsの作成
- PRの壁（ブランチ保護、CI必須、CODEOWNERS）と、AIレビューの自動化

**やらないこと**

- AWSなどへのリリース（別ワークフローとして、あとで作る）
- 外部の人からのPRへの対応（内輪での利用が前提）
- mutation testingなど高度な検証（困ってから足す）

## マイルストーン

まず履歴の引き継ぎ(M0)を片付け、テンプレート、壁、実践の順に進めます。期日は未定です。

1. M0：devcontainerで過去のClaude Code履歴を見られるようにする（\~/.claudeをマウントし、pluginsだけ別volumeにして、履歴が見えるか確認）
2. M1：テンプレートリポジトリ（TypeScriptとVitest、devcontainer、CLAUDE.mdのTDDルール、test-reviewer）
3. M2：PRの壁（ブランチ保護、CI必須、CODEOWNERS）
4. M3：カートAPIでSDDとTDDを実際に回し、速さと信頼を確かめる
5. M4：Skills化、ghとClaude CLIによるAIレビュー、docs系の自動マージ
6. M5以降：mutation testing、差分カバレッジ、依存変更の人間チェック、リリース用の別ワークフロー

## リスク、成功の見方、次の一歩

最大のリスクは、作り込みすぎて進まなくなることです。1マイルストーンずつ進め、困ってから足します。

| リスク | 対策 |
| --- | --- |
| AIが通すための小細工をする | テストの期待値を書き換えない。diffをたまに見る。test-reviewerで別の目を入れる |
| \~/.claudeの共有で認証情報が漏れる | イメージに焼き込まない。コンテナの権限を絞る |
| 自動マージで壊れる | パス条件で振り分ける。CI必須にする。すぐ戻せる状態を保つ |
| 作業フォルダのパスが違い、履歴が見えない | M0で実際に確認し、見えなければ同期の方法を検討する |

**成功の見方**

- コンテナ内で、過去のClaude Code履歴を見られる
- カートAPIの1機能をTDDで回し、人間が見たのはテスト名と期待値だけで済んだ
- docs系のPRが、人手を介さずマージされる

**次の一歩**

M0として、devcontainer.jsonに\~/.claudeのマウントを追加し、過去の履歴が見えるか試します。
