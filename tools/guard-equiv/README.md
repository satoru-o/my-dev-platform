# guard-equiv: guard の判定が、基準と同一かを確かめる道具

`.claude/hooks/` の guard を直した（分ける、整える、移す）あとで、**判定が変わっていないこと**を機械で確かめる。0011 で作り、0012 でリポジトリに入れた。

## 使い方
```
uv run python tools/guard-equiv/run.py
```
- 基準を取り出し、同じ入力の一覧（Edit・Write、Bash、巨大なファイル、CRLF、git なし。約1850件）を、基準といまの版に通す。判定の理由とスイッチの消費まで、JSON で比べる。
- 全件一致なら終了コード0。違えば、違う入力を表示して、終了コード1。所要時間は約4分（入力ごとに、使い捨ての git リポジトリを作るため）。
- 「新規・削除・内容不明・解析しきれない」の入力が含まれていることも、毎回表示する（`worker.py` の `required_keys`）。

## 基準
分割前のコミット `55adc1b92167f2d3441eaf00b252365aef3e6a1b`（0011 の開始時点。`guard.py` が1193行の版）の hash で固定している（`run.py` の `BASELINE`）。`git show <hash>:.claude/hooks/guard.py` で取り出す。**リポジトリ内にコピーは置かない**（コピーが書き換わると、基準が動くため）。

意図して判定を変えるとき（段階6の誤検出の緩和など）は、不一致が出るのが正しい。そのときは、基準を、人間の承認を得て、新しい hash に更新する（`BASELINE` の変更は、req に書く）。

## 検出力
基準と比べる道具が「何も検出しない」のでは意味がないので、導入時に、わざと1文字違う版（`git reset --hard` の判定）を作り、32件が不一致になることを確かめた（0011）。

## 段階4への申し送り（人間の指示）
`tools/guard-equiv/` は、守りの検査の基準を作る道具なので、**段階4で、保護パスに足す**（`guardlib/paths.py` の `PROTECTED` と、`settings.json` の `permissions.deny`）。足さないと、AI が、道具か基準の hash を書き換えて、「判定は同一」と言えてしまう。0012 では足していない（足すのは段階4、という人間の指示。保護パスの変更は `.claude/**` の編集で、別の req で、UNLOCK のもとで行う）。
