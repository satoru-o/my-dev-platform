### Q1. 書き込み先が変数のとき、どう判定する？
- シナリオ: python の heredoc で、`p='CLAUDE.md'` のように、先にパスを変数に入れてから `open(p,'w')` で書く。今は「コマンドのどこかに保護パスの文字列がある」ことで拒否している。誤検出を直すと、この判定の根拠がなくなるので、「変数に入った文字列」を見る必要がある。
- 選択肢:
  - A. 代入が見えるものは、その値で判定する（`p='CLAUDE.md'` は拒否、`p='specs/a.md'` は通す）。**代入が見えない**もの（`p=sys.argv[1]`）は、**拒否**（安全側。誤検出は Write ツールか UNLOCK で避ける）
  - B. 代入が見えるものは、その値で判定する。代入が見えないものは、**今までどおり通す**（見逃しは残る。ベストエフォート）
  - C. 変数経由は判定しない（直接 `open('CLAUDE.md','w')` と書いたときだけ拒否する）
- 推奨: B
- 推奨の理由: この要望は「誤検出の修正」。A は見逃しを塞ぐ変更で、別の要望にしたほうが範囲が小さく保てる。ただし、`p='CLAUDE.md'` を拒否のままにするには、代入を読む仕組みがどのみち要る（C は今の拒否を通す退行になる）。見逃しは「やらないこと」に書いたとおり、ベストエフォートの限界として残る。セキュリティ優先で塞ぎたいなら A。
- 回答: B

### Q2. heredoc の本文は、どう扱う？
- シナリオ: `cat > specs/x.md <<'EOF'` の本文は、ファイルに書く「文章」で、実行されない。本文の行頭に `touch .claude/x` と書いてあっても、ただの文章。一方 `bash <<'EOF'` や `python3 - <<'EOF'` の本文は、そのまま**実行される**。今は、どちらも本文を同じように調べるので、前者が誤検出になる。
- 選択肢:
  - A. heredoc を受け取るコマンドで分ける。`cat`、`tee`、`git commit -F -` など、**データとして受け取るだけ**なら本文を調べない（書き込み先は、`>` の先で別に判定する）。`bash`、`sh`、`python` など、**インタプリタ**なら本文を調べる
  - B. heredoc の本文は、いつも調べない
  - C. heredoc の本文は、いつも調べる（今のまま。誤検出が残る）
- 推奨: A
- 推奨の理由: B は `bash <<EOF` 経由の回り込みを許す退行になる。C は誤検出が残る。A は、実行されるかどうかという実際の違いに合わせる。判定できないコマンドは、インタプリタとして扱う（安全側）。
- 回答: A

### Q3. 「書き込み」とみなす python の関数の範囲は？
- シナリオ: 今は、`open(…,'w'/'a'/'x'/'+')`、`write_text`、`write_bytes`、`.write(`、`shutil.copy/move/rmtree`、`os.remove/rename/replace/unlink` を書き込みとみなす。ほかに、`os.system('rm …')`、`subprocess.run(['rm', …])`、`Path.touch()`、`mkdir` などもあるが、今は見ていない。
- 選択肢:
  - A. 今の範囲のまま（この要望では広げない）
  - B. 上のような関数も足す
- 推奨: A
- 推奨の理由: 「やらないこと」に「完全な防御にしない」と書いたとおり。広げると、誤検出の修正から離れて、検出を増やす要望になる。必要なら別の要望にする。
- 回答: A

### Q4. 引用符なしの heredoc で、本文の `$(…)` はどう扱う？
- シナリオ: `cat > specs/x.md <<EOF`（`EOF` を引用符で囲まない）の本文では、シェルが `$(…)` とバッククォートを**展開して実行する**。本文に `$(touch .claude/x)` と書くと、cat はデータを受けるだけでも、その touch は実行される。Q2=A（データを受けるだけなら本文を調べない）のままだと、ここが抜け穴になる。
- 選択肢:
  - A. 引用符なしの heredoc は、本文の `$(…)` とバッククォートの中身を調べる（保護対象への書き込みなら拒否）。`<<'EOF'` と `<<"EOF"`（引用符あり）は、本文を調べない
  - B. 引用符なしでも、本文は調べない（抜け穴が残る）
  - C. 引用符なしの heredoc は、本文に `$(` かバッククォートがあれば、中身にかかわらず拒否する
- 推奨: A
- 推奨の理由: 実行されるかどうかの実際の違いに合わせる。B は、この要望が避けたい「拒否すべきものが通る」退行になる。C は誤検出が増える（`$(date)` のような無害なものも止まる）。
