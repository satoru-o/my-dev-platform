# テスト観点カタログ（初版）

test-planは、観点ごとに1行で「適用 / 適用しない」を判断する。
「適用しない」には必ず理由を書く。リスクタグ付きの要望では X-01〜X-04 を「適用しない」にできない。

## 入力

| ID | 観点 | 例 |
| --- | --- | --- |
| V-01 | 空 | 空文字、空配列、null、未指定 |
| V-02 | 0・負数・最大値・最大+1 | 0、-1、上限ちょうど、上限+1 |
| V-03 | 型違い・全角・絵文字・改行 | 数値の代わりに文字列、`１２３`、`🍎`、`a\nb`。型の暗黙変換を黙って受け入れない（文字列の数値 `"2"`、数値の文字列、真偽値 true→1 など。0001で `"2"` が通っていた） |
| V-04 | 巨大な入力 | 非常に長い文字列、大量の要素 |

## 状態

| ID | 観点 | 例 |
| --- | --- | --- |
| S-01 | 対象が存在しない | 存在しない商品ID、存在しないカート |
| S-02 | 重複 | 同じ商品を2回追加 |
| S-03 | 同じ操作の繰り返し | 同じリクエストを連続送信（冪等性） |
| S-04 | 別の対象が互いに影響しない | 2つのカート、2人のユーザー。片方への操作が、もう片方に出ない（0001 の FB 2 で、カートIDを無視する実装がテストで見逃されていた） |

## セキュリティ

| ID | 観点 | 例 |
| --- | --- | --- |
| X-01 | 未認証・権限なし | トークンなしで呼ぶ |
| X-02 | 他人のデータ | 他人のカートIDを指定して操作 |
| X-03 | 危険な文字列（SQL・パス・コマンド） | `'; DROP TABLE--`、`../../etc/passwd`、`; rm -rf` |
| X-04 | エラーに内部情報が出ない | スタックトレース、ファイルパス、SQLがレスポンスに出ない |

## 出力

| ID | 観点 | 例 |
| --- | --- | --- |
| O-01 | エラー形式の統一 | すべてのエラーが同じJSON形式（code、message） |
| O-02 | 金額の丸めと単位 | 小数の丸め、円とセントの取り違え |

## 運用メモ
- バグを見つけたら、直す前にテストを足し、その種類をこの表に観点として足す（人間の承認を得る）。
- 観点IDは欠番を埋めず、末尾に足す。
