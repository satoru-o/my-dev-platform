# test-plan（0007 test-change-guard / サイズ: S2）

S2 なので、観点カタログ（`specs/_catalog/viewpoints.md`）の全14行を評価する。「適用しない」には理由を書く。`⚠️` はAIが自信のない行（G2で見てほしい）。理由と選択肢は `discussion-log.md` の Round 3 に書いた。
ここは「テストのリスト」まで。テストコードは1件ずつ、Red→Greenで書く。テストは `.claude/hooks/test_guard.py` に足す（`tests/` ではない。`guard.py` の判定を、関数として呼んで確かめる）。

## テストの順序（S2。1件ずつ。今通るもの＝退行の網は、先に足す）

1. 退行の網: 新しいテスト関数の追加、新規ファイル、parametrize への値の追加 → 通る（AC-1）
2. **Red**: assert 行の削除 → 拒否（AC-2。HEAD との比較の最小の実装）
3. **Red**: 期待値の変更 → 拒否（AC-2）
4. **Red**: skip / xfail / `pytestmark`（既存への追加、新しいテストの中）→ 拒否（AC-2）
5. **Red**: テスト関数の削除、既存ファイルの丸ごとの置き換え → 拒否（AC-2）
6. **Red**: 未コミットのテストは、自由に直せる（AC-2、Q2=B）
7. **Red**: `conftest.py`・補助モジュールへの同じ判定（Q5=A）
8. **Red**: Bash 経由の、既存テストファイルへの書き込み → 拒否。まだ無いファイル → 通る（Q3=A）
9. **Red**: スイッチ（人間だけが置ける、1回で消える、守る対象に触れない呼び出しでは消えない）（AC-3）
10. **Red**: git 操作（常に拒否するもの、守る対象に触れるときだけ拒否するもの、「全部」を指すパス、通すもの）（AC-4）
11. **Red**: pytest の設定（`pyproject.toml` は、該当の節だけを比べる）（AC-5）
12. **Red**: `req.md` の AC の表（実装中の変更・削除を拒否、足すのは通す、AC 番号をキーにする）（AC-6）
13. V-04: 巨大な入力が、2秒以内（別プロセス、上限で打ち切る）
14. S-04 / X-03 / V-03: 別の書き方（パス、改行、日本語）、解析しきれないもの
15. Q11（`HEAD` が取れないとき）: コミット0件、`git` の失敗、タイムアウト、環境変数の掃除（別々のテスト）
16. Q12（同名の定義）: 関数、同じクラスのメソッド、代入での上書き、別のクラスのメソッド

## 迷いどころ
なし（Round 3 の Q10〜Q12 は回答済み。`⚠️` の行も無い）。
