# 0001 cart-add-item

## やりたいこと
カートAPIで「商品を追加する」。追加できるのは商品IDと数量のみ（価格・合計・丸めは範囲外）。


## 受け入れ条件
<!-- 各ACに、具体的な入出力の例を2〜3個。期待値は必ずあなたが書く。AIは埋めない -->

### AC-1
<!-- 例: 「商品をカートに追加できる」 -->

| 入力 | 期待される出力 |
| --- | --- |
| POST /carts/c1/items {"product_id": "p1", "quantity": 2} | 201、カート c1 は p1 x 2 |
| 続けて {"product_id": "p2", "quantity": 1} | 201、カート c1 は p1 x 2 と p2 x 1 |

### AC-2
<!-- 例: 「同じ商品をもう一度追加したとき」 -->

| 入力 | 期待される出力 |
| --- | --- |
| p1 x 2 のあとに p1 x 3 を追加 | 201、カート c1 は p1 x 5 |
| p1 x 1 のあとに p1 x 1 を追加 | 201、カート c1 は p1 x 2 |

### AC-3 カートは、カートIDごとに独立している（FB 2、Q9）

| 入力 | 期待される出力 | 出典 |
| --- | --- | --- |
| `POST /carts/c1/items {"product_id": "p1", "quantity": 2}` のあと、`POST /carts/c2/items {"product_id": "p2", "quantity": 1}` | 201、カート c2 は **p2 x 1 だけ**（c1 の p1 は入らない） | [案→承認] |
| `POST /carts/c1/items {"product_id": "p1", "quantity": 2}` のあと、`POST /carts/c2/items {"product_id": "p1", "quantity": 3}` | 201、カート c2 は **p1 x 3**（c1 の数量と合算されない） | [案→承認] |

### AC-4 合算の境界は、ちょうど99まで通る（FB 2、Q10）

| 入力 | 期待される出力 | 出典 |
| --- | --- | --- |
| p1 x 98 のあとに p1 x 1 を追加 | 201、カートは **p1 x 99** | [案→承認] |
| p1 x 50 のあとに p1 x 49 を追加 | 201、カートは **p1 x 99** | [案→承認] |
| p1 x 99 のあとに p1 x 1 を追加 | **422**（カートは p1 x 99 のまま） | [案→承認] |

### AC-5 商品 p3 も追加できる（FB 2、Q11）

| 入力 | 期待される出力 | 出典 |
| --- | --- | --- |
| `POST /carts/c1/items {"product_id": "p3", "quantity": 1}` | 201、カート c1 は **p3 x 1** | [案→承認] |

## やらないこと
- 価格の取り扱い、合計金額、金額の丸め
- 認証・認可、ユーザーごとのカートの所有・分離（カートIDごとの独立は AC-3 で確かめる）
- 永続化（まずはメモリ上でよい）

## 制約
- FastAPI、Python。時刻・乱数が必要なら外から渡す
- （Round 1 回答）カートは初回の追加で暗黙に作られる
- （Round 1 回答）商品は固定の小さなマスタ（p1, p2, p3）。マスタに無いIDは404
- （Round 1 回答）数量は1〜99の整数のみ。範囲外・型違いは422。合算後に99を超える場合も422
- （Round 1 回答）レスポンスはカート全体 `{"cart_id", "items": [{"product_id", "quantity"}]}`、itemsは追加順
- （Round 1 回答）エラーは `{"error": {"code", "message"}}` に統一し、内部情報を出さない
- （Round 2 回答）数量の上限99は、カートに入れる段階の暫定値。在庫の引き当て可能量や決済時の支払い能力の検証は別機能で扱い、必要になったら上限を変える
- （Round 2 回答）合算して99を超える追加は422を返し、カートは変わらない
- （Round 2 回答）「内部情報が出ない」は、エラー本文が `error` の中の `code` と `message` だけであることで確認する
- （FB 2、Q12=A）エラーの `code` は契約にする（機械が読む識別子）。存在しない商品（404）は `product_not_found`、数量の範囲外・型違い・必須項目の欠落（422）は `invalid_request`、合算が99を超える（422）は `quantity_exceeded`。`message` は人間向けの文言で、変えてよいので固定しない
